> 不确定日志到底在哪个文件？别猜，跑 `bash GPU_交给师兄/诊断.sh` ——
> 它会**自己挑最新的那个日志**，并在第 0 节明确打印「我在读哪个文件」。

**关于 `nohup: ignoring input`（必读，很多人在这里被吓到）**：

`nohup bash ... > GPU_交给师兄/守护.out 2>&1 &` 跑起来后，`守护.out` 里出现

```
nohup: ignoring input
```

这是 **正常现象，不是报错**。它的意思是：nohup 把标准输入从终端摘掉（改成 `/dev/null`），
这样你关掉终端、断开 SSH 之后任务也不会被挂断。就这一句话，后面不会有别的内容。

**日志到底在哪**：`重启_6小时版.sh`（v2 及以后）把看守输出写进 `看守.log`，
并把 `守护.out` 做成指向它的软链 —— 所以 `tail` 哪个名字都能看到实时进度。

⚠️ **例外**：如果你看到 `守护.out` 里除了 `nohup: ignoring input` 之外什么都没有、
而 `看守.log` 又报 `No such file or directory`，那说明这次是用**已删除的老 `守护.sh`** 启的。
换成 `重启_6小时版.sh` 重来即可，或者先跑 `诊断.sh` 定位当前日志到底在哪个文件。

**60 秒体检**（不确定任务死活时先跑这个，只读不写）：

```bash
bash GPU_交给师兄/诊断.sh
```

它会打印：看守日志在哪个文件（它自己挑最新的）、`run_all.py` 进程在不在、
开始/完成/失败/跳过的计数、显卡占用、已完成多少折、最新任务日志的尾巴、汇总表有没有生成。
把整段输出回传即可，不用自己判断。

## 每一步是干什么的（想看细节再看，不看也行）

| 步骤 | 干什么 | 为什么做 | 大概多久（6900 样本、单卡） |
|---|---|---|---|
| `检查` | 自检环境和数据（**顺带确认能不能找到元数据表**） | 别白跑一整天 | 3 分钟 |
| `打包数据` | 把 .pt 打成一个内存映射文件 | **训练提速 2–3 倍**（治 CPU 瓶颈） | 5–15 分钟（只做一次） |
| `数据流` | 数一遍「原始条目 → 去重 → 各实验类型 → 实际建模样本」，并生成 0D/2D 描述符清单 | 回答审稿人「数据都用在哪了」+ 补充材料要的描述符表 | 1 分钟 |
| `消融` | 分别去掉 cliff 损失、3D、0D、2D 分支再训练 | 回答"每个模块有多少贡献" | 8–16 小时（8 卡） |
| `构象` | 用 1/2/3/5/10 个构象各训一遍 | 回答"为什么用 10 个构象" | 3–6 小时 |
| `种子` | 换 5 个随机种子重跑 full vs wo_3d | 证明结论不是运气（**只有这一步跑多 seed**） | 8–16 小时（8 卡） |
| `严格` | 做一个"测试集分子在训练集里找不到相似邻居"的测试集 | **论文主结果**，回答"数据泄漏了吗" | 4–7 小时 |
| `骨架` | 按分子骨架划分，测试没见过的骨架 | 回答"能泛化到新化学空间吗" | 4–7 小时 |
| `留出` | 普通随机划分（对照组） | 展示随机划分会高估多少 | 4–7 小时 |
| `来源` | 按文献来源留一 | 回答"跨来源还好用吗" | 4–8 小时 |
| `预处理` | 把 Caco2 等端点做成同样的四视图数据 | 分 assay 实验的前置 | 10–30 分钟（CPU） |
| `分assay` | 在 Caco2 上单独训练评估 | 回答"换个实验类型还能用吗" | 1 小时（Caco2 只有 649 个样本） |
| `基线` | 随机森林 / SVM，同样的划分和特征 | 回答"深度模型比传统方法强吗" | 几分钟（CPU） |
| `悬崖` | 统计全库"相似结构但渗透率差很多"的分子对 | 回答"模型懂化学细节吗" | 几分钟（CPU） |
| `出表` | 把所有结果汇总成论文表格 | 直接贴进补充材料 | 秒级 |
| `划分` | 导出所有划分文件（谁在训练集/测试集/第几折） | 回应 R1「公开数据划分」 | 1–2 分钟 |
| `出图` | **用真实预测**重画所有图 | 旧出图脚本是合成分数画的，必须换掉 | 1–2 分钟 |
| `特征` | 导出隐层特征 + 调好超参的 t-SNE | 回应 R1 对图 5B「丝状伪影」的质疑 | 1 次训练（约 2 h） |
| `导出数据` | 样本清单 + 构象生成参数 + 数据可得性说明 | 写 Data Availability 用 | 1 分钟 |
| `写作映射` | 表/图 ↔ 数据文件对照表 | 写稿时照着填，不用再找 | 秒级 |

**打包数据之后，总工作量 ≈ 140 次训练**：8 卡 ≈ 1 天；共享机器 3 卡 ≈ 1.5–2 天；只跑上面那四步 ≈ 半天。**没打包的话速度大约只有一半**，所以务必先跑 `打包数据`。
第一个折跑完后日志里会显示真实用时，可以据此估算总时间。

## 三条不许动的规矩

1. **不要动 `run_all.py` 里 0D 特征的 log1p 那一行**。
   原始数据里 RDKit 的 Ipc 最大到 4e36，不处理的话整批 loss 会变成 NaN ——
   之前那批结果不稳定就是这个原因。（自检里会打印这条的诊断，可以自己看。）
2. **不要改 `src/model.py` 的输入维度**（view4=729、view2=200）。
3. **不要挑种子、不要挑折**：所有 seed、所有折的结果都回传；日志里 `nan` 不为 0 的折要单独说一声。

## 常见问题

**Q：提示「没有找到元数据表」，然后 9 个步骤都被拦住了？**
A：脚本找不到「生成这批 .pt 用的那张表」。它会自动去这几个地方找（按顺序）：
数据目录里的 `sample_manifest.csv` → `/data/workplace/jwx/MSF-CPMP/datasets_process/CycPeptMPDB_Peptide_PAMPA.csv`
→ `/data/workplace/jwx/cycpeptmp/data/CycPeptMPDB_Peptide_{PAMPA,All}.csv` → 项目目录下的同名文件。
自动找不到时，它会**在自检阶段就停下来**并打印可以照抄的命令，例如：
```bash
python GPU_交给师兄/run_all.py --meta-csv /data/workplace/jwx/MSF-CPMP/datasets_process/CycPeptMPDB_Peptide_PAMPA.csv
```
或者把那张表拷进数据目录改名：
```bash
cp /data/workplace/jwx/MSF-CPMP/datasets_process/CycPeptMPDB_Peptide_PAMPA.csv \
   /data/workplace/jwx/TV-STFN/tetraview_processed/sample_manifest.csv
```
（给的是全 assay 表也行：脚本会用 PAMPA 列自动筛出 6941 行。）

**Q：报错 "元数据与 .pt 对不上"？**
A：说明 `--meta-csv` 指的那张表不是生成这批 `.pt` 用的表（或者顺序不一样）。
先停下来发我，**不要**硬跑 —— 那会让所有按 SMILES 做的划分全错。

**Q：报错 "找不到 TV-STFN 项目根目录"？**
A：文件夹放错位置了。必须放在 TV-STFN 项目根目录下（同级能看到 `src/`）。

**Q：报错 "RDKit 描述符数 = xxx，但数据是用 217 生成的"？**
A：只影响 `预处理` 那一步（生成新数据）。训练不需要，继续跑其他步骤即可。

**Q：想连断点都看得懂？**
A：每个折结束时 `results/<任务>/folds/*.json` 会落盘，`preds/*.csv` 是逐样本预测。
中断不会丢已经算完的折。

**Q：以前的旧脚本呢？**
A：都在 `_history/` 里，包含之前那版复杂脚本和各种分析记录（比如为什么上一批结果要重跑）。
**不要用它们**，现在只需要 `run_all.py` 一个程序。
